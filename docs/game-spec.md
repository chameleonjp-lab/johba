# 要件仕様書：スマホブラウザ向け 騎手視点3D競馬ゲーム（仮題「ジョッキーズアイ」）

## 0. この文書について

この文書は、Claude Code に開発を依頼するための要件仕様書です。依頼者からの確定要件をもとに、未確定だった点は開発上適切と考えられる内容でこちらで確定しています。確定した判断には「【決定事項】」と付記しているので、変更したい場合はその箇所だけ指示し直せば差し替えられます。

**参考ビジュアル**：依頼者提供のスクリーンショット（騎手の背後やや上からの三人称視点、芝コース、多頭数のレース、左右に操作ボタン、上部にスピード/パワーゲージと残距離表示）。この画面構成をビジュアルの基準イメージとします。

---

## 1. ゲームコンセプト

プレイヤーは騎手としてレースに騎乗し、ゲートインからゴールまでを騎手目線（馬上後方カメラ）で操作する。鞭を入れるタイミング、道中の位置取り、スタミナの配分、馬場や天気と馬の相性、他馬との駆け引きを考えながら1着を目指す、リアル志向のレースゲーム。

- 1プレイ = 1レース完結（ゲート→ゴール→順位発表→結果画面）
- 騎乗馬は自分で完全には選べない。出走表を見て「乗りたい馬」を3頭希望し、その中から抽選で1頭が割り当てられる
- 順位とタイムでスコアが決まる

## 2. 動作環境・技術要件

| 項目 | 内容 |
|---|---|
| 対象端末 | スマートフォンのブラウザ（iOS Safari / Android Chrome)。縦持ち・横持ちは**横持ち推奨、縦持ちでも崩れない**こと |
| 実装形式 | **単一HTMLファイル**（CSS / JavaScript をすべて内包）【決定事項】 |
| 3D描画 | Three.js（CDN読み込み、バージョンは最新安定版を固定指定）【決定事項】 |
| サーバ | 不要（スタンドアロンで動作）。第13章のオンラインランキングのみ Supabase を任意で使用 |
| パフォーマンス目標 | ミドルレンジ端末で30fps以上、可能なら60fps。馬はローポリ＋ジョイント単純化アニメーションで描画負荷を抑える |
| 入力 | タッチ操作のみで完結（マウスでも一応動作すること） |
| 通信 | ゲーム本体はオフラインで動作。フォントや画像の外部依存は最小限に |

### パフォーマンス設計の指針
- 馬モデルはプリミティブ（箱・円柱・球）の組み合わせ、またはコードで定義した簡易ジオメトリで構成し、外部3Dモデルファイルは使わない
- 出走頭数ぶんの馬はジオメトリとマテリアルを共有（InstancedMesh または clone でマテリアル共有）
- 影はプレイヤー馬のみ、または擬似影（地面の楕円）で代用可
- 描画距離の遠い馬はアニメーション更新頻度を落とす（参考：依頼者の既存作で実績のある「描画ループの性能ゲーティング」と同じ考え方）

## 3. 画面遷移（フロー）

```
[タイトル]
   ↓ タップでスタート
[レース条件発表]  …距離・天気・馬場の発表
   ↓
[出走表]  …全12頭のスペック確認（一部は非公開情報あり）
   ↓
[騎乗希望の選択]  …3頭を選んで申請
   ↓
[騎乗馬発表]  …抽選結果。「あなたの騎乗馬は◯番◯◯！」
   ↓
[ゲート前演出]  …短いカウントダウン
   ↓
[レース本編]  …ゲート→ゴール（騎手視点3D）
   ↓
[順位発表演出]  …掲示板風に1着から順に表示
   ↓
[結果画面]  …自分の着順・タイム・スコア・リプレイ要素なしの簡易講評
   ↓ 「もう一度」でレース条件発表へ / タイトルへ戻る
```

【決定事項】騎乗馬の発表タイミングは「ゲート前」ではなく出走表選択の直後とする。発表後にその馬の全スペック（非公開だった気性・調子も含む）が開示され、プレイヤーは作戦を立ててからゲートインできる。

## 4. レース条件（毎回ランダム生成）

| 項目 | バリエーション | 影響 |
|---|---|---|
| 距離 | 1200m / 1600m / 2000m / 2400m から抽選 | 距離適性との相性、スタミナ配分の難度 |
| 天気 | 晴 / 曇 / 雨 | 雨は馬場を悪化させる。各馬の道悪適性が効く |
| 馬場状態 | 良 / 稍重 / 重 / 不良（天気と連動して抽選） | 全体の走破速度低下＋道悪適性による個体差 |
| コース | 芝・左回り・平坦【決定事項：初版は1コース固定】 | 視覚は参考画像準拠（芝、白柵、遠景にビル） |
| 出走頭数 | 12頭固定【決定事項】 | 画面密度と処理負荷のバランスから決定 |

## 5. 馬のスペック（毎回ランダム生成・12頭）

実際の競馬の馬の個性に寄せた構成とする。内部値は 0〜100 の数値、出走表での表示は S/A/B/C/D の5段階表記。

### 5.1 公開ステータス（出走表で見える）
| 項目 | 意味 |
|---|---|
| スピード | 最高速度の高さ |
| スタミナ | 速度を維持できる距離の長さ |
| 瞬発力 | 加速の鋭さ。直線での伸び |
| パワー | 道悪・坂・馬群を割る力 |
| 脚質 | 逃げ / 先行 / 差し / 追込 のいずれか |
| 距離適性 | 得意距離帯（短距離寄り〜長距離寄り） |
| 馬場適性 | 道悪が得意か苦手か（◎○△✕） |

### 5.2 非公開ステータス（騎乗馬発表後に自分の馬だけ開示）【決定事項】
| 項目 | 意味 |
|---|---|
| 気性 | 折り合いの難しさ。悪いと「掛かり」やすい（後述） |
| 当日の調子 | 全能力に ±10% 程度の補正 |
| ゲート | スタートの上手さ（出遅れ確率に影響） |

### 5.3 生成のバランス調整
- 12頭の能力合計がレースごとに極端に偏らないよう、総合値の平均が一定範囲に収まるよう正規化する
- 脚質は12頭の中で逃げ1〜2頭、先行3〜4頭、差し4〜5頭、追込2〜3頭程度の分布になるよう重み付き抽選
- 「弱い馬に乗っても展開と騎乗次第で馬券圏内（3着以内）が狙える」程度の能力差に収める

---

## 6. 騎乗馬の決定方式

1. 出走表を見て、乗りたい馬を**3頭**選択する
2. 3頭の中から**等確率（各1/3）の抽選**で騎乗馬が決まる【決定事項：人気や能力による重み付けはしない】
3. 抽選演出（数秒のドラム的演出）の後に発表

## 7. レース本編：操作仕様

参考画像のレイアウトを踏襲し、**左右の親指だけで全操作が完結する**ことを必須とする。

### 7.1 操作一覧
| 操作 | 入力 | 効果 |
|---|---|---|
| ゲートスタート | 発走の合図に合わせてタップ | タイミングが良いほど好スタート。早すぎ・遅すぎは出遅れ |
| 仕掛ける（加速） | 右下「▲」ボタンを押す/長押し | ペースを上げる。スタミナ消費が増える |
| 抑える（温存） | 左下「▼」ボタンを押す/長押し | ペースを落としスタミナ回復寄りに。掛かり防止にも使う |
| 進路変更 | 画面中央付近を左右スワイプ、または左右端タップ【決定事項：両対応】 | 内/外のレーンへ1段階移動。前が詰まっている時の進路確保に必須 |
| 鞭 | 右下の鞭専用ボタンを連打不可のタップ | 数秒間の強い加速。使用ごとにスタミナを大きく消費し、短時間に連打すると効果が減衰（実際の競馬の使用制限の雰囲気を再現） |

### 7.2 ゲーム内パラメータ（HUD表示）
- **スタミナゲージ**（最重要。残量で末脚の伸びが決まる）
- **スピードゲージ**
- 現在の**順位**と**残り距離**（例：`12番手 / 残り1133m`）
- ラップ感覚を掴むための**現在ペース表示**（ハイ/ミドル/スロー の3段階表記）【決定事項：数値ラップではなく直感的表記にする】
- 鞭の使用可否アイコン

## 8. レースのシミュレーション仕様（リアル志向の中核）

### 8.1 スタミナと速度のモデル
- 各馬は「巡航速度」「最高速度」「現在スタミナ」を持つ
- 速度が巡航を超えるほどスタミナ消費が加速度的に増える
- スタミナが一定値を切ると最高速度が段階的に低下（「バテ」の表現）。ゼロになると大きく失速する
- 距離適性が合わない馬はスタミナ消費係数が悪化する

### 8.2 位置取りと駆け引き
- **スリップストリーム（風よけ）**：前の馬の真後ろにつけるとスタミナ消費が約15%軽減される【決定事項：数値は調整前提の初期値】
- **前が壁**：前方と斜め前を他馬に塞がれると、加速しても速度が前の馬に制限される。外に持ち出すか、馬群が割れるのを待つ判断が必要
- **外を回すロス**：コーナーで外のレーンほど走行距離が伸びる（実際の競馬と同じ）。内は距離得だが包まれやすい
- **掛かり**：気性の悪い馬で序盤にペースを上げすぎる、または抑え操作を怠ると「掛かり」状態になり、操作を受け付けずスタミナを浪費する。抑えボタンの長押しで徐々に解消

### 8.3 AI馬の挙動
- 各AI馬は自分の脚質に従って走る（逃げ馬は先頭を主張、追込馬は後方待機→直線勝負）
- 逃げ馬が複数いるとペースが上がり（ハイペース）、前の馬が終盤バテやすくなる。逃げ馬不在ならスローペースで前残りしやすい——**展開がレースごとに変わる**ことを必ず再現する
- AIにも進路選択・仕掛けタイミングの個体差を持たせ、毎回同じレースにならないようにする

### 8.4 天気・馬場の影響
- 道悪（稍重〜不良）では全馬の基礎速度が低下し、パワーと馬場適性の高い馬ほど低下幅が小さい
- 雨天時は視覚演出（空の色、雨パーティクルは軽量に）も変更する

## 9. カメラ・ビジュアル

- カメラは**自馬の後方やや上**に追従（参考画像と同じ視点）。速度に応じてわずかに視野角と揺れが変化し、スピード感を出す
- 直線とコーナーで構成された周回コース。ゴール板、ハロン棒（200mごとの距離標識）、内柵・外柵を配置
- 騎手の勝負服は馬ごとに色違いで自動生成し、出走表の枠番色と対応させる
- ゴール前は接戦時のみスローモーション演出を入れてよい（任意・軽量に実装できる場合のみ）

---

## 10. スコア計算【決定事項】

```
スコア = 着順基礎点 + タイムボーナス
着順基礎点：1着1000 / 2着600 / 3着400 / 4着250 / 5着150 / 6着以下は着順に応じて100〜10
タイムボーナス：距離ごとに定めた「基準タイム」より速かった0.1秒につき +5点（上限300点）
```
- 基準タイムは距離・馬場状態ごとにテーブルで持つ（道悪は基準を緩める）
- 結果画面にスコアの内訳を表示する

---

## 11. 順位発表・結果画面

1. ゴール後、**掲示板演出**：1着から順番にゼッケン番号と馬名がせり上がって表示される（接戦の場合「写真判定」の文字を一拍挟む演出を入れる）
2. 結果画面に表示する内容：
   - 自分の着順・馬名・走破タイム
   - スコアと内訳
   - 全12頭の最終着順表
   - 一言講評（例：「スタミナを残して直線に向けた好騎乗」「仕掛けが早く最後に脚が上がった」など、レース中のデータから条件分岐で生成）【決定事項：定型文の条件分岐でよい。AI生成は不要】
3. 「もう一度走る」「タイトルへ」ボタン

---

## 12. 出走表画面の仕様

- 12頭を枠番・ゼッケン・馬名・公開ステータス（5段階表記）・脚質・馬場適性の一覧で表示
- 馬名はカタカナ9文字以内で自動生成（語感パーツの組み合わせ。実在馬名との一致は偶然に委ねてよい）
- 各馬をタップすると詳細カードが開く
- 希望3頭の選択はこの画面上でチェックして「申請」ボタンで確定

## 13. オンラインランキング（任意・実装できれば）

ChameleonJP ポータルの既存ゲームと同様に、Supabase によるスコアランキングを実装する。
- 送信内容：プレイヤー名（端末保存）、スコア、着順、距離、日時
- 接続失敗時はゲーム進行を妨げずローカル表示のみにフォールバック
- Supabase の URL / anon キーはファイル先頭の設定定数にまとめ、差し替えやすくする

※ ランキングを後回しにする場合も、スコア計算と結果画面は本仕様どおり実装すること。

## 14. 受け入れ条件（完成の定義）

1. iPhone の Safari と Android の Chrome の実機相当環境で、タイトルから結果画面まで通しでプレイできる
2. 12頭立てのレース中、ミドルレンジ端末想定で操作遅延を感じない（目安30fps以上）
3. 同じ条件で3回プレイして、展開（ペース・着順）が毎回変わる
4. 強い馬を引いても騎乗ミス（掛かり・スタミナ切れ・前が壁）で負けることがあり、弱い馬でも展開がはまれば3着以内に入れる
5. 鞭・仕掛け・抑え・進路変更のすべてが結果に体感できる差を生む
6. 文字・ボタンがスマホ縦横どちらでも操作可能なサイズで表示される
